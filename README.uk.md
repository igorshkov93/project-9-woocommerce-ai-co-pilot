# WooCommerce AI Co-pilot

AI-асистент для власників магазинів на WooCommerce, що працює через Telegram.
Відповідає на аналітичні питання про магазин, готує чернетки маркетингових
текстів і виконує адміністративні дії природною мовою — на основі LLM
tool-calling, оркестрація в n8n.

> Статус: основні сценарії реалізовані та працюють наскрізно; триває фінальна
> перевірка двох нещодавніх виправлень.

## Навіщо це потрібно

Керування невеликим магазином на WooCommerce означає постійне перемикання
між wp-admin, таблицями та маркетинговими інструментами лише для того, щоб
відповісти на рутинне питання або виконати рутинну дію. Цей асистент замінює
це перемикання розмовою в Telegram:

- **"Як пройшов цей тиждень?"** — замість того щоб вручну збирати звіт,
  власник питає простою мовою і одразу отримує зведення, або отримує його
  автоматично щодня у вигляді дайджесту в Slack.
- **Лист для повернення покупця з покинутим кошиком** — замість написання
  тексту з нуля, асистент готує чернетку в стилі магазину, на запит.
- **Цільовий купон для категорії, що погано продається** — замість того щоб
  розбиратися в інтерфейсі купонів WooCommerce і вручну визначати категорію,
  власник просто описує, що потрібно, і підтверджує пропозицію перед тим, як
  щось буде створено. Жодна дія не записується в магазин без явного
  підтвердження людиною.

Мета: перетворити щоденне адміністрування магазину на повідомлення в
Telegram, яке займає п'ять секунд, не надаючи LLM неконтрольований доступ на
запис у магазин.

## Можливості

- Щоденні зведення по замовленнях і виручці
- Аналіз товарів з найбільшою кількістю повернень
- Чернетки листів для покинутих кошиків
- Створення купонів з підтвердженням людиною
- Заплановий щоденний дайджест у Slack

## Технологічний стек

| Шар | Технологія |
|---|---|
| Інтерфейс | Telegram Bot API |
| Оркестрація | n8n (self-hosted, Docker) |
| Reasoning | Gemini Flash (маршрутизація, tool calling), Claude Haiku (генерація тексту) |
| Векторне сховище | Qdrant |
| Джерело даних | WooCommerce REST API |
| Сповіщення | Slack (прямий виклик API — див. [ADR 0009](docs/adr/0009-orders-digest-to-slack.md)) |

## Архітектура

Єдиний Telegram-шлюз маршрутизує кожне вхідне повідомлення або натискання
кнопки до воркфлоу AI Agent, який працює з шістьма інструментами (запити до
магазину, аналітика, пропозиція купона, чернетки листів, дайджест у Slack),
кожен зі своїм саб-воркфлоу. Дії, що змінюють стан магазину (створення
купона), проходять через явний потік propose → confirm: агент може лише
*запропонувати*, і нічого не створюється, доки власник не натисне кнопку
підтвердження, яка запускає окремий, вузько сфокусований воркфлоу.

Архітектурні рішення та їхні компроміси задокументовані як ADR у
[docs/adr/](docs/adr/):

- [0008 — Оркестрація AI-агента](docs/adr/0008-ai-agent-orchestration.md)
- [0009 — Дайджест замовлень у Slack](docs/adr/0009-orders-digest-to-slack.md)
